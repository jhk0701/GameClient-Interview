## 1. 자료구조

### Q1. 자료구조가 뭔가요?
- **정의:** 데이터를 효율적으로 저장하고 접근하기 위해 정해진 규칙에 따라 데이터를 조직화하는 방법입니다.
    - 키워드 : 
    (목적) 데이터의 효율적인 저장 및 접근,
    (구현) 정해진 규칙에 따른 데이터 조직화한 것

- **설명:** 어떤 자료구조를 쓰느냐에 따라 탐색·삽입·삭제의 시간복잡도가 달라지므로, 상황에 맞는 자료구조 선택이 성능에 직결됩니다.

- **예시:** 파쿠르 시스템에서 후보 지형 지점들을 트리 형태로 구성해 동적 raycast 판단에 활용하신 것처럼, 자료구조 선택 자체가 알고리즘 설계의 전제가 됩니다.

### Q2. std::array or 일반 배열과 std::vector(동적 배열)의 차이는?
- **정의:** 배열은 고정 크기의 연속된 메모리 블록, vector는 동적으로 크기가 조정되는 연속 메모리 컨테이너입니다.

- **설명:** 배열은 크기가 컴파일 타임에 고정되어 재할당 비용이 없지만 유연성이 없습니다. vector는 내부적으로 capacity를 초과하면 더 큰 메모리 블록을 새로 할당하고 기존 데이터를 복사하는 방식으로 동작합니다. 이 재할당 과정에서 O(n) 비용이 발생할 수 있습니다.

- **예시:** 크기가 고정된 그리드 데이터는 배열, 런타임에 개수가 변하는 오브젝트 목록은 vector가 적합합니다.

### Q3. 배열과 연결리스트(Linked List)의 차이는?
- **정의:** 배열은 연속 메모리에 데이터를 저장하고, 연결리스트는 노드가 포인터로 서로를 가리키며 흩어져 저장됩니다.

- **설명:** 배열은 인덱스 접근이 O(1)이지만 중간 삽입/삭제가 O(n)입니다. 연결리스트는 접근은 O(n)이지만, 위치를 이미 알고 있다면 삽입/삭제가 O(1)입니다. 캐시 지역성 측면에서는 연속 메모리인 배열이 유리합니다.

- **예시:** 빈번한 순회·인덱스 접근이 필요하면 배열/vector, 빈번한 중간 삽입·삭제가 필요하면 연결리스트를 고려합니다.

### Q4. 스택과 큐의 차이와 활용 예시는?
- **정의:** 스택은 LIFO(후입선출), 큐는 FIFO(선입선출) 구조입니다.

- **설명:** 스택은 함수 호출 스택, 실행 취소(undo) 기능 등에 쓰이고, 큐는 이벤트 처리 순서 보장이나 BFS 탐색 등에 사용됩니다.

- **예시:** 애니메이션 몽타주에서 재생 대기 중인 노티파이 이벤트를 순서대로 처리할 때 큐 구조를 떠올릴 수 있습니다.

### Q5. 해시맵(unordered_map)의 내부 동작 원리는?
- **정의:** 키를 해시 함수로 변환한 값을 인덱스로 사용해 데이터를 저장하는 자료구조입니다.

- **설명:** 키의 해시값을 계산해 버킷 인덱스를 정하고, 같은 인덱스에 여러 키가 몰리는 해시 충돌은 체이닝(연결리스트)이나 오픈 어드레싱으로 처리합니다. 평균 시간복잡도는 O(1)이지만, 충돌이 심하면 최악의 경우 O(n)까지 저하될 수 있습니다.

- **예시:** 커스텀 엔진에서 액터를 ID로 빠르게 조회할 때, 배열 순회 대신 해시맵 기반 조회를 쓰면 조회 비용을 크게 줄일 수 있습니다.

### Q6. 트리 자료구조는 언제 사용하나요?
- **정의:** 노드 간 계층적 부모-자식 관계로 데이터를 표현하는 비선형 자료구조입니다.

- **설명:** 탐색·삽입·삭제가 균형 트리 기준으로 O(log n)이며, 계층 구조나 우선순위가 있는 데이터 표현에 적합합니다.

- **예시:** 파쿠르 시스템의 동적 raycast tree처럼, 후보 지형을 트리 구조로 구성해 조건에 따라 가지치기(pruning)하며 탐색하는 방식이 대표적인 실무 예시입니다.

## 2. 알고리즘 & 복잡도

### Q1. 시간복잡도(Big-O)란 무엇인가요?
- **정의:** 입력 크기가 커질 때 알고리즘의 실행 시간이 어떻게 증가하는지를 나타내는 표기법입니다.

- **설명:** 최악의 경우를 기준으로 상수항을 무시하고 증가율만 표현합니다. O(1) < O(log n) < O(n) < O(n log n) < O(n²) 순으로 효율이 낮아집니다.

- **예시:** 배열에서 특정 값을 찾을 때 순차 탐색은 O(n), 정렬된 배열에서 이진탐색은 O(log n)입니다.

### Q2. 정렬 알고리즘 하나를 설명해보세요 (예: 퀵소트).
- **정의:** 퀵소트는 피벗을 기준으로 작은 값과 큰 값을 분할한 뒤 재귀적으로 정렬하는 분할정복 알고리즘입니다.

- **설명:** 평균 시간복잡도는 O(n log n)이지만, 피벗 선택이 나쁘면 최악의 경우 O(n²)까지 저하됩니다. 머지소트는 항상 O(n log n)을 보장하지만 추가 메모리가 필요합니다.

- **예시:** 게임 내 오브젝트를 거리순으로 정렬해 우선순위 처리할 때, 데이터 특성(거의 정렬된 데이터인지 등)에 따라 알고리즘을 선택합니다.

### Q3. 이진탐색은 어떤 조건에서 쓸 수 있나요?
- **정의:** 정렬된 데이터에서 중간값과 비교하며 탐색 범위를 절반씩 줄여가는 탐색 방법입니다.

- **설명:** 전제 조건은 데이터가 정렬되어 있어야 한다는 점이며, 시간복잡도는 O(log n)입니다.

- **예시:** 정렬된 거리 기반 후보 리스트에서 특정 임계값 이하의 지점을 빠르게 찾을 때 활용할 수 있습니다.

### Q4. 재귀와 반복문의 차이, 재귀 사용 시 주의점은?
- **정의:** 재귀는 함수가 자기 자신을 호출해 문제를 작은 단위로 쪼개는 방식이고, 반복문은 루프로 동일한 동작을 되풀이하는 방식입니다.

- **설명:** 재귀는 코드가 직관적이지만 매 호출마다 스택 프레임이 쌓이므로 깊이가 깊어지면 스택 오버플로우 위험이 있습니다. 종료 조건이 명확해야 하며, 필요시 꼬리 재귀나 반복문으로 전환해 최적화합니다.

- **예시:** 트리 순회는 재귀로 구현하기 쉽지만, 트리 깊이가 매우 깊을 수 있는 경우 반복문 기반 스택 순회로 바꾸는 것이 안전합니다.

### Q5. DFS와 BFS의 차이는?
- **정의:** DFS(깊이우선탐색)는 한 방향으로 끝까지 파고든 뒤 되돌아오는 방식, BFS(너비우선탐색)는 가까운 노드부터 차례로 넓게 탐색하는 방식입니다.

- **설명:** DFS는 스택(재귀 포함)을, BFS는 큐를 사용합니다. 최단 경로가 필요하면 BFS, 모든 경로 탐색이나 백트래킹에는 DFS가 적합합니다.

- **예시:** 파쿠르 지형 후보를 탐색할 때, 가장 가까운 도달 가능 지점을 우선적으로 찾고 싶다면 BFS 방식의 사고가 필요합니다.

## 3. 객체지향(OOP) 핵심 개념

### Q1. 객체지향의 4대 특성을 설명해보세요.
- **정의:** 캡슐화, 추상화, 상속, 다형성입니다.

- **설명:** 캡슐화는 데이터와 로직을 하나로 묶고 접근을 제한하는 것, 추상화는 공통 특성만 추출해 인터페이스로 표현하는 것, 상속은 부모의 특성을 자식이 물려받는 것, 다형성은 같은 인터페이스로 다른 동작을 수행하는 것입니다.

- **예시:** 커스텀 엔진의 Actor-Component 구조 자체가 컴포넌트 단위 캡슐화와, 공통 인터페이스를 통한 다형적 처리의 예시가 될 수 있습니다.

### Q2. 상속과 다형성을 실제 코드 관점에서 설명해보세요.
- **정의:** 상속은 base class의 멤버를 derived class가 물려받는 것, 다형성은 base class 포인터/레퍼런스로 여러 파생 클래스의 동작을 각기 다르게 실행하는 것입니다.

- **설명:** C++에서 다형성은 가상함수(virtual)와 함께 동작하며, base 클래스 포인터로 호출해도 실제 객체 타입의 오버라이드된 함수가 실행됩니다(동적 바인딩).

- **예시:** 보스 패턴별 카운터 공격 판정을 base BehaviorNode에서 가상함수로 정의하고, 각 패턴 클래스에서 오버라이드하는 구조를 예로 들 수 있습니다.

### Q3. 오버로딩과 오버라이딩의 차이는?
- **정의:** 오버로딩은 같은 이름의 함수를 매개변수가 다르게 여러 번 정의하는 것, 오버라이딩은 부모 클래스의 가상함수를 자식 클래스에서 재정의하는 것입니다.

- **설명:** 오버로딩은 컴파일 타임에 어떤 함수를 호출할지 결정되고(정적 바인딩), 오버라이딩은 런타임에 실제 객체 타입에 따라 결정됩니다(동적 바인딩).

- **예시:** 함수 이름은 같지만 매개변수 개수·타입이 다른 유틸 함수들은 오버로딩, 애니메이션 노티파이 콜백을 파생 클래스마다 다르게 구현하는 것은 오버라이딩입니다.

### Q4. 인터페이스(추상클래스)와 일반 상속의 차이는?
- **정의:** 추상클래스는 공통 기본 구현과 순수 가상함수를 함께 가질 수 있는 클래스이고, 인터페이스는 구현 없이 함수 시그니처만 정의합니다(C++에서는 순수 가상함수만 있는 클래스로 구현).

- **설명:** 추상클래스는 "is-a" 관계의 공통 기반을 제공하고, 인터페이스는 서로 다른 계층의 클래스에 동일한 기능 계약을 강제할 때 사용합니다.

- **예시:** AI Perception 확장 시 PlayerAction 감지 인터페이스를 정의해두면, 서로 다른 보스 클래스들이 이를 각자의 방식으로 구현하도록 강제할 수 있습니다.

## 4. C++ 메모리 관리 (UE5 실무 직결 — 중요도 높음)

### Q1. 스택과 힙의 차이는?
- **정의:** 스택은 함수 호출과 함께 자동으로 할당·해제되는 메모리 영역이고, 힙은 프로그래머가 직접(또는 스마트포인터로) 할당·해제를 관리하는 메모리 영역입니다.

- **설명:** 스택은 할당 속도가 빠르지만 크기가 제한적이고 함수 종료 시 자동 해제됩니다. 힙은 크기 제약이 적지만 할당 비용이 크고, 해제를 잊으면 메모리 누수가 발생합니다.

- **예시:** 지역 변수나 값 타입은 스택에, new로 생성한 객체나 UE5의 UObject는 힙에 할당됩니다.

### Q2. 포인터와 레퍼런스의 차이는?
- **정의:** 포인터는 메모리 주소를 저장하는 변수로 재할당과 null이 가능하고, 레퍼런스는 변수의 별칭으로 한 번 초기화되면 재할당이 불가능합니다.

- **설명:** 포인터는 nullptr을 가질 수 있어 유효성 검사가 필요하지만, 레퍼런스는 항상 유효한 대상을 참조한다는 전제가 있습니다.

- **예시:** 함수 인자로 값을 반드시 전달받아야 하고 null 가능성이 없다면 레퍼런스, 소유권 이전이나 null 가능성이 있다면 포인터를 사용합니다.

### Q3. 스마트포인터(unique_ptr, shared_ptr)를 쓰는 이유는?
- **정의:** 스마트포인터는 객체의 수명을 자동으로 관리해 메모리 누수를 방지하는 RAII 기반 포인터 래퍼입니다.

- **설명:** unique_ptr은 단독 소유권을 가지며 복사가 불가능하고, shared_ptr은 참조 카운트를 기반으로 여러 곳에서 공유 소유가 가능합니다. delete를 직접 호출하지 않아도 스코프를 벗어나면 자동으로 해제됩니다.

- **예시:** UE5는 UObject 계열에 자체 가비지 컬렉션(UPROPERTY 기반)을 쓰지만, 순수 C++ 객체나 커스텀 엔진에서는 스마트포인터로 수명 관리를 직접 설계해야 합니다.

### Q4. 가상함수와 vtable, 가상소멸자가 필요한 이유는?
- **정의:** 가상함수는 런타임에 실제 객체 타입에 맞는 함수가 호출되도록 하는 메커니즘이며, vtable은 이를 위해 클래스별로 만들어지는 함수 포인터 테이블입니다.

- **설명:** base 클래스 포인터로 derived 객체를 delete할 때, 소멸자가 가상이 아니면 base 클래스의 소멸자만 호출되어 derived 부분의 자원이 해제되지 않는 문제가 생깁니다. 이를 막기 위해 다형적으로 사용되는 클래스는 가상 소멸자를 선언해야 합니다.

- **예시:** BehaviorNode 같은 base 클래스를 다형적으로 사용하고 포인터로 delete하는 구조라면, 가상 소멸자 누락이 실제 메모리 누수로 이어질 수 있습니다.

### Q5. UE5의 UPROPERTY 기반 가비지컬렉션과 순수 C++ 메모리 관리의 차이는?
- **정의:** UE5는 UPROPERTY로 표시된 UObject 참조를 추적해 자동으로 가비지 컬렉션을 수행하지만, 순수 C++ 메모리는 개발자가 직접 수명을 관리해야 합니다.

- **설명:** UPROPERTY가 없는 raw 포인터는 GC 추적 대상이 아니므로 댕글링 포인터 위험이 있고, 반대로 커스텀 엔진처럼 UE5 프레임워크가 없는 환경에서는 스마트포인터나 명시적 참조 카운팅으로 이를 대체해야 합니다.

- **예시:** 펄어비스 인턴십에서 다루신 자체 C++/DirectX11 엔진은 UE5의 GC 프레임워크가 없는 환경이므로, 이 차이를 직접 비교해서 설명할 수 있는 실전 경험 포인트입니다.

## 5. 디자인 패턴 (게임 개발 면접 단골)

### Q1. 싱글톤 패턴이란?
- **정의:** 클래스의 인스턴스가 프로그램 전체에서 단 하나만 존재하도록 보장하는 패턴입니다.

- **설명:** 생성자를 private으로 막고, 정적 메서드를 통해서만 유일한 인스턴스에 접근하도록 합니다. 전역 상태에 가까워 과용하면 테스트나 의존성 관리가 어려워질 수 있다는 단점도 함께 언급하면 좋습니다.

- **예시:** 게임 매니저, 리소스 매니저처럼 전역적으로 하나만 필요한 시스템에 흔히 사용됩니다.

### Q2. 옵저버 패턴이란?
- **정의:** 한 객체(subject)의 상태 변화를 구독 중인 여러 객체(observer)들에게 자동으로 알리는 일대다 의존성 패턴입니다.

- **설명:** 발행자와 구독자가 서로 직접 참조하지 않아도 되므로 결합도가 낮아지고, 이벤트 기반 시스템 설계에 자주 쓰입니다.

- **예시:** 보스의 특정 애니메이션 노티파이가 발생했을 때 카운터 판정 시스템이 이를 구독해 반응하는 구조를 예로 들 수 있습니다.

### Q3. 오브젝트 풀 패턴이란?
- **정의:** 객체를 매번 생성·삭제하지 않고 미리 만들어 둔 풀에서 꺼내 재사용하는 패턴입니다.

- **설명:** 빈번한 동적 할당·해제로 인한 성능 오버헤드와 메모리 단편화를 줄이는 것이 목적입니다.

- **예시:** 총알, 파티클처럼 빈번하게 생성·소멸되는 오브젝트에 적용해 런타임 성능을 최적화합니다.

## 6. 일반 C/C++ CS 지식 (게임 여부와 무관하게 자주 나오는 항목)

*이 섹션은 4번(C++ 메모리 관리)과 겹치지 않는 범위에서, C/C++ 직군 면접 전반에 걸쳐 반복적으로 나오는 언어 자체의 특성을 다룹니다.*

### Q1. C와 C++의 차이는 무엇인가요?
- **정의:** C는 절차지향 언어이고, C++은 C를 확장해 객체지향·제네릭 프로그래밍을 함께 지원하는 멀티패러다임 언어입니다.

- **설명:** C++은 클래스·상속·다형성·템플릿·예외처리·참조 등을 추가로 제공하며, STL 같은 표준 라이브러리를 통해 자료구조와 알고리즘을 재사용할 수 있습니다.

- **예시:** 데이터와 로직을 캡슐화한 컴포넌트 구조를 설계할 때 C++의 클래스 기반 접근이 유리합니다.

### Q2. static 키워드를 상황별로 설명해보세요.
- **정의:** 변수나 함수의 수명과 접근 범위를 확장하거나(정적 수명) 특정 범위로 제한하는 키워드입니다.

- **설명:** 지역변수에 붙이면 함수 호출이 끝나도 값이 유지되고, 전역변수·함수에 붙이면 해당 파일 내부로만 접근이 제한되며(내부 링크), 클래스 멤버에 붙이면 모든 인스턴스가 하나의 값을 공유합니다.

- **예시:** 정적 멤버변수로 클래스의 전체 인스턴스 개수를 카운팅하는 것이 대표적인 활용입니다.

### Q3. const는 어떻게 쓰이나요? (const 포인터, const 멤버함수)
- **정의:** 값이 변경되지 않음을 컴파일러가 보장하도록 하는 키워드입니다.
- **설명:** `const int* p`는 가리키는 값이 상수라는 뜻이고, `int* const p`는 포인터 자체가 상수라는 뜻입니다. 멤버함수 뒤에 붙는 const는 그 함수가 멤버 변수를 변경하지 않는다는 것을 보장합니다.
- **예시:** getter 함수는 대부분 const 멤버함수로 선언해 객체 상태를 바꾸지 않는다는 의도를 명확히 드러냅니다.

### Q4. C++ 컴파일 과정을 설명해보세요.
- **정의:** 소스코드가 실행파일이 되기까지 전처리 → 컴파일 → 어셈블 → 링크 단계를 거칩니다.

- **설명:** 전처리 단계에서 매크로 치환과 include 삽입이 이뤄지고, 컴파일 단계에서 어셈블리 코드로, 어셈블 단계에서 오브젝트 파일(기계어)로 변환된 뒤, 링크 단계에서 여러 오브젝트 파일과 라이브러리를 하나의 실행파일로 결합합니다.

- **예시:** 헤더에는 선언만 두고 include guard를 쓰는 이유도 이 컴파일 단위 개념과 직결됩니다.

### Q5. 구조체(struct)와 클래스(class)의 차이는?
- **정의:** C++에서는 문법적으로 거의 동일하며, 기본 접근제한자만 다릅니다(struct는 public, class는 private).

- **설명:** 관례적으로 구조체는 단순한 데이터 묶음(POD)에, 클래스는 캡슐화된 동작(메서드)이 포함된 객체에 사용합니다.

- **예시:** 좌표값만 담는 Vector3는 구조체로, 복잡한 로직을 가진 게임 오브젝트는 클래스로 설계하는 것이 일반적인 관례입니다.

### Q6. 얕은 복사와 깊은 복사의 차이, 복사생성자가 필요한 이유는?
- **정의:** 얕은 복사는 포인터가 가리키는 주소값만 복사하고, 깊은 복사는 가리키는 데이터까지 새로 복제합니다.

- **설명:** 클래스가 힙 메모리를 가리키는 포인터 멤버를 가질 때 기본 복사생성자는 얕은 복사를 수행하므로, 두 객체가 같은 메모리를 가리키게 되고 하나가 소멸되면 다른 객체는 댕글링 포인터를 갖게 됩니다. 이를 막기 위해 복사생성자와 대입연산자를 직접 정의(깊은 복사)해야 합니다.

- **예시:** 동적 배열을 멤버로 가진 클래스를 복사할 때 이 문제를 실제로 마주칠 수 있습니다.

### Q7. 캐스팅의 종류(static_cast, dynamic_cast, reinterpret_cast, const_cast)를 설명해보세요.
- **정의:** C++은 목적에 따라 네 가지 명시적 캐스팅 연산자를 제공합니다.

- **설명:** static_cast는 컴파일 타임에 안전성이 검증되는 일반적 형변환, dynamic_cast는 런타임에 상속 관계를 확인하며 실패 시 nullptr(포인터)나 예외(레퍼런스)를 반환하는 다형적 캐스팅, reinterpret_cast는 타입을 무시하고 비트 그대로 재해석하는 위험한 캐스팅, const_cast는 const성을 제거·추가하는 캐스팅입니다.

- **예시:** base 클래스 포인터를 특정 파생 클래스로 안전하게 변환해 고유 함수를 호출할 때 dynamic_cast를 사용합니다.

### Q8. 다중상속과 다이아몬드 문제란?
- **정의:** 다중상속은 한 클래스가 둘 이상의 base 클래스를 상속받는 것이고, 다이아몬드 문제는 두 base 클래스가 같은 조상을 가질 때 그 조상 멤버가 중복 상속되어 모호해지는 문제입니다.

- **설명:** C++에서는 virtual 상속을 사용해 공통 조상을 한 번만 공유하도록 해결합니다.

- **예시:** 순수 가상 인터페이스를 여러 개 구현하는 다중상속은 실무에서 흔히 쓰이지만, 상태를 가진 다중상속은 다이아몬드 문제 때문에 신중하게 설계해야 합니다.

### Q9. 예외처리(try/catch)와 RAII는 어떤 관계인가요?
- **정의:** 예외처리는 런타임 오류 발생 시 정상 흐름을 벗어나 처리 코드로 이동하는 메커니즘이고, RAII는 객체의 생성자·소멸자에 자원 획득과 해제를 묶는 설계 원칙입니다.

- **설명:** 예외로 인해 스택이 풀리는(stack unwinding) 과정에서도 스코프를 벗어나는 지역 객체의 소멸자는 호출되므로, RAII로 자원을 관리하면 예외 상황에서도 자원 누수 없이 안전하게 해제됩니다. 스마트포인터가 대표적인 RAII 적용 사례입니다.

- **예시:** raw 포인터로 자원을 직접 관리하면 예외 발생 시 해제 코드를 건너뛸 위험이 있지만, RAII 래퍼를 쓰면 이 문제가 사라집니다.

### Q10. 매크로(#define)와 인라인 함수의 차이는?
- **정의:** 매크로는 전처리 단계에서 단순 텍스트로 치환되고, 인라인 함수는 컴파일러가 타입 체크를 거쳐 호출부에 코드를 삽입하도록 제안하는 함수입니다.

- **설명:** 매크로는 타입 안전성이 없어 괄호 누락 등으로 의도치 않은 연산 순서 문제가 생기기 쉬운 반면, 인라인 함수는 일반 함수처럼 타입 검사와 디버깅이 가능합니다.

- **예시:** 상수는 #define보다 constexpr, 짧은 반복 로직은 매크로보다 inline 함수로 작성하는 것이 현대 C++ 관례입니다.

### Q11. 헤더 가드(include guard)와 extern은 왜 필요한가요?
- **정의:** 헤더 가드는 같은 헤더가 여러 번 include될 때 중복 정의 오류를 막는 전처리 지시문(#ifndef/#define/#endif 또는 #pragma once)이고, extern은 변수·함수가 다른 파일에 정의되어 있음을 알리는 선언 키워드입니다.

- **설명:** 여러 소스파일이 같은 헤더를 include하는 대규모 프로젝트에서 필수적이며, extern은 전역 변수를 여러 .cpp 파일에서 공유할 때 사용합니다.

- **예시:** 여러 모듈로 나뉜 프로젝트에서 헤더 가드 누락은 컴파일 에러의 흔한 원인입니다.

### Q12. undefined behavior(정의되지 않은 동작)란 무엇인가요?
- **정의:** C++ 표준이 결과를 규정하지 않아 컴파일러·플랫폼마다 다르게 동작할 수 있는 코드 상태입니다.
- **설명:** 배열 범위를 벗어난 접근, 초기화되지 않은 변수 사용, 널 포인터 역참조, 이중 해제(double free) 등이 대표적 예시이며, 당장 문제가 없어 보여도 최적화 옵션이나 플랫폼이 바뀌면 예상치 못한 버그로 나타날 수 있습니다.
- **예시:** 디버그 빌드에서는 정상 동작하다가 릴리즈 빌드에서 크래시가 나는 경우, undefined behavior를 의심해볼 수 있습니다.
