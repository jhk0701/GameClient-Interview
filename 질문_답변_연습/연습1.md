# C++ 기초
1. 포인터와 참조의 차이점
    * 포인터는 다른 변수의 메모리 주소를 가리키는 방식입니다.
        * 포인터는 nullptr를 가리킬 수 있습니다.
        * 포인터는 재할당이 가능해서 다른 데이터의 메모리 주소를 가리킬 수 있습니다.
    * 참조는 다른 변수에 별명을 지어주고 원본에 접근할 수 있도록하는 방식입니다.
        * 참조의 대상이 되는 변수는 반드시 NULL이 아닌 값으로 초기화되어 있어야합니다.
        * 한번 초기화된 참조 변수는 재할당이 불가능합니다.
2. new와 malloc의 차이점
    * malloc은 C언어에서 동적할당하는 방식입니다.
        * 'stdlib.h'에서 제공하는 함수입니다.
        * malloc의 경우 생성 시, 할당받을 메모리의 크기를 매개변수로 보내주어야 합니다.
        * malloc의 매개변수로 초기화 값을 보낼 수 없습니다.
        * 반환받는 결과가 void* 이기 때문에 사용 시 원하는 포인터로 형변환 해주어야합니다.
        * malloc으로 동적할당 받은 경우 realloc 등으로 메모리 크기를 변경할 수 있습니다.
    * new는 C++에서 사용하는 동적할당 방식입니다.
        * C++ 언어에서 지원하는 키워드입니다.
            * 그래서 별도의 라이브러리 include가 필요없습니다.
        * new를 사용할 때, 동적할당할 자료형을 이용합니다. 
            * 이 때문에 별도로 크기를 명시할 필요가 없습니다.
        * new로 동적할당 시, 초기화값을 설정할 수 있습니다.
        * 반환받는 결과는 동적할당할 때 사용한 자료형의 포인터입니다.
        * new로 동적할당한 주소의 메모리 크기는 변경할 수 없습니다.
3. C++ 4대 캐스팅 방법에 대한 설명해 주세요.
    * C++에서 지원하는 캐스팅 방법은 `static_cast`, `dynamic_cast`, `reinterpret_cast`, `const_cast`가 있습니다.
    * `static_cast` :
        * 컴파일 타임에서 타입의 형변환이 가능한지 확인하고 형변환시킵니다.
        * 형변환이 불가능한 경우 컴파일 에러를 발생시킵니다.
        * 상속 관계에 있는 경우 다운캐스팅 시, 타입 안정성을 보장하지 않습니다.
    * `dynamic_cast` :
        * 런타임 중에 캐스팅하려는 타입이 맞는지 검사합니다.
        * 불가능할 경우, nullptr을 반환합니다.
        * 런타임에 타입 안정성 검사를 진행하고 상속 관계에서 업캐스트나 변환을 지원해주지만,
        다른 데이터형 변환은 허용하지 않습니다.
            * 주로 다형성을 가진 클래스의 포인터나 참조 간의 변환에 사용합니다.
    * `reinterpret_cast` :
        * 모든 포인터 유형을 다른 포인터 방식으로 변경하는 방법입니다.
        * 비트단위부터 분해, 재조립하는 강력한 형변환을 수행합니다.
    * `const_cast` :
        * `const`나 `volatile`를 제거, 부여하는데 사용하는 방법입니다.
        * 타입 자체보다는 객체의 속성을 변경하는데 초점을 맞춥니다.
            * 추가보단 제거에 주로 사용합니다.
4. RTTI와 RAII의 차이점에 대해서 설명해 주세요.
    * RTTI (Run Time Type Information : 런타임 타입 식별)
        * 런타임 중 객체의 타입 정보를 식별할 수 있는 기능입니다.
            * C++ 언어에서 제공하는 매커니즘.
        * 다형성이 있는 클래스에만 사용가능합니다.
        * 가상테이블에 저장된 타입 정보를 확인하는 방식을 사용합니다.
    * RAII (Resource acquisition is initialization : 자원 획득은 초기화에 한다)
        * 객체 생성 시 리소스를 획득하고, 소멸 시 리소스를 해제하는 방식을 의미합니다.
            * 객체가 생성될 때 자원을 획득한다.
            * 객체가 소멸될 때 자원을 해제한다.
            * 객체의 소멸은 스코프 종료 시 자동으로 보장된다.
        * C++에선 메모리, 락, 파일, 소켓 등 다양한 자원을 직접 관리할 수 있습니다.
            * 하지만 이때, 자원 정리를 누락하는 경우로 인해서 비효율이 발생할 수 있습니다.
            * 이런 경우를 방지하기 위해서 RAII 방식을 사용하여 자원의 획득과 해제를 보장합니다.
        * 스마트포인터나 mutex를 사용한 LockGuard 등에서 사용합니다.
5. C++ 스마트포인터에 대해서 설명해 주세요
    * 스마트포인터는 원시 포인터를 사용하고 나서 해제하지 않고 누락하는 것을 방지하기 위해 만들어진 기능입니다.
    * 포인터 관리 뿐만 아니라 메모리의 권한(소유권)을 명시하는 의도로 사용할 수 있습니다.
        * 스마트포인터는 메모리에 대한 권한 처리 방법에 따라 세 종류가 있습니다.
        * Shared_ptr, Weak_ptr, Unique_ptr 세 종류
    * Shared_ptr
        * 여러 곳에서 데이터의 메모리에 대한 참조가 가능한 스마트 포인터입니다.
        * 메모리를 참조하는 횟수를 기록하고, 횟수가 0이 될때 메모리를 해제합니다.
        * 즉, 참조 횟수를 기반으로 데이터의 수명을 유지시켜 줍니다.
            * 원시 포인터로 동적할당된 데이터를 공유할 때, 한 곳이라도 먼저 데이터를 해제시켜버리면, 참조 중인 다른 곳에선 댕글링 포인터를 사용하는 위험이 따릅니다.
            * shared_ptr는 이런 문제를 방지할 수 있습니다.
    * Weak_ptr
        * shared_ptr에 대해 참조 횟수를 올리지 않고, 참조할 수 있는 포인터입니다.
        * 메모리 생명 유지에 영향을 주지 않고 참조할 수 있기에 순환 참조로 인한 메모리 누수를 방지할 수 있습니다.
        * 또한, 참조 횟수를 올리지 않기 때문에 댕글링 포인터가 발생할 수 있습니다.
            * 이 때문에 weak_ptr는 가리키는 데이터가 유효한지 검증하는 메서드를 제공하고 있습니다.
    * Unique_ptr
        * 메모리를 한 곳에서만 소유하도록 보장하는 포인터입니다.
            * 데이터의 소유 주체를 명시할 수 있습니다.
        * 복사 대입 생성자를 제거했기 때문에 포인터를 복사할 수 없습니다.
            * 단, move semantic이나 release 함수를 사용하여 포인터의 소유권을 넘겨줄 수 있습니다.
        * 데이터를 소유한 객체가 소멸해 참조가 없어지면 데이터를 같이 해제합니다.
6. 객체 복사를 막는 방법은 어떤 방법이 있을까요? 왜 객체 복사를 막아야 할까요?
    * 객체 복사를 막는 방법으로
        * C++ 11 이후 버전에선 복사 대입 연산자, 복사 생성자를 delete 키워드로 삭제하는 것입니다.
        * C++ 11 이전 버전에선 복사 대입 연산자, 복사 생성자를 private에 선언하는 것입니다.
    * 객체 복사를 막는 이유로는
        1. 리소스의 중복 소유를 막기 위해서입니다.
            * 파일 핸들, 소켓, 스레드 핸들, 메모리 버퍼 등은 하나의 객체만 소유해야 안전하게 관리됩니다.
            * 얕은 복사로 인한 이중 해제의 위험을 방지하기 위해 객체의 복사를 막을 수 있습니다.
        2. RAII 기반 클래스에서 리소스 누수 방지하기 위해서입니다.
            * Unique_ptr같은 move-only 객체처럼 이동만 허용하고 복사를 금지하기 위해서 복사를 막을 수 있습니다.
            * 복사하면 같은 포인터를 두 객체가 소유하는 문제를 발생할 수 있습니다.
        3. 복사 비용을 절감하기 위해서입니다.
            * 복사 비용이 매우 큰 객체의 무분별한 복사를 방지하기 위해서입니다.
            * 대규모 메모리 버퍼, 게임엔진의 리소스, 네트워크 I/O 관련한 무거운 객체들
               * 이런 객체가 실수로 복사되면 성능에 큰 문제가 생깁니다.
        4. 객체의 논리적 의미가 '복사 불가능한 경우'
            * 싱글턴 객체 : 복사되면 싱글턴이 아니게 됨
            * 뮤텍스 : 복사 불가능
            * 파일 스트림
            * std::thread : thread는 복사가 불가능하고 이동만 가능
            * 이런 클래스는 복사 자체가 개념적으로 불가능하다.
## 자료구조
1. std::list와 std::vector의 차이점에 대해서 설명해 주세요
    * 둘다 같은 타입을 선형적으로 나열하는 자료구조
    * 둘의 가장 큰 차이점은 요소의 메모리 상 배치 방식에 있습니다.
    * vector는 동일한 타입의 요소를 메모리 상에 연속되게 배치하는 `동적 배열` 자료구조입니다.
        * 이런 특징으로
            - 탐색 : O(1)
            - 삽입, 삭제 : O(n)
        시간 복잡도를 가집니다.
    * list는 요소가 메모리 상에 연속적으로 배치되지 않습니다.<br>
    하나의 요소 뒤에 다음 요소를 가리키는 포인터를 가지고 있습니다.
        * 이런 특징으로
            - 탐색 : O(n)
            - 삽입, 삭제 : O(1)
        시간 복잡도를 가집니다.
2. std::map에 대해서 설명해 보세요.
    * 균형 이진 트리를 이용하여 key-value 쌍을 이루어주는 자료구조입니다.
    - 균형 이진 트리 구조이기 때문에
        - 탐색 : O(log n)
        - 삽입, 삭제 : O(log n)
        시간 복잡도를 갖습니다.
    - 균형 이진 트리를 통해 key의 값을 기준으로 정렬됩니다.
3. std::unordered_map에 대해서 설명해 주세요
    * 해시 테이블을 이용하여 key-value 쌍을 이루어주는 자료구조입니다.
    - 해시 함수를 이용하여 key의 해시값을 버킷의 인덱스에 사용하고 그 위치에 value를 넣습니다.
        - 탐색 : 평균적으로 O(1), 최악의 경우 O(n)
        - 삽입, 삭제 : 평균적으로 O(1), 최악의 경우 O(n)
        시간 복잡도를 갖습니다.
    * 해시를 이용하기 때문에 요소들이 정렬되지 않습니다.
    * 3-1. 꼬리 질문 남기기
        * 최악의 경우 O(n)의 시간 복잡도를 갖는 이유는 해시 함수의 특징으로 인해 해시 충돌이 발생하기 때문입니다.
        * 해시라는 것이 어떤 값을 고정된 길이의 정수 값으로 바꾸는 것입니다.
            * 이 때문에 모든 값을 고정된 길이에 담을 수 없고 결국 중복이 발생합니다.
            * 이러한 현상을 해시 충돌이라고 합니다.
        * 해시 충돌을 해결하기 위해 고안된 방법들이 있습니다.
            - 개방 주소
            - 체이닝 
        * unordered_map은 체이닝을 이용해 해시 충돌을 해소합니다
            - 충돌난 key 값의 해시를 리스트나 트리 형태로 묶어 버킷에 저장합니다.
            - 이 과정에서 key의 값을 탐색하기 때문에 최악의 경우 O(N)의 시간복잡도가 발생합니다.
        * 해시 충돌은 요소가 많아질수록 발생할 확률이 증가합니다.
4. std::find와 std::binary_search의 차이를 설명해주세요.
    * std::find는 주어진 자료구조를 순회하며 원하는 값을 찾는 방식입니다.
        - 이 알고리즘의 시간 복잡도는 O(N)입니다.
        - 반환하는 결과가 원하는 원소의 iterator 입니다.
            - 찾지 못하면 end() iterator를 반환합니다.
        - find는 주어진 자료구조가 정렬되지 않아도 사용가능합니다.
    * std::binary_search는 주어진 자료구조를 이진탐색을 통해 값을 찾는 방식입니다.
        - 이진탐색을 이용하므로 시간 복잡도는 O(log N)입니다.
        - bool을 반환하여 원하는 요소의 존재유무를 결과로 나타냅니다.
        - 이진탐색은 자료구조가 정렬된 상태를 전제로 올바르게 작동합니다.
    * 요소의 원하는 위치를 알고 싶다면 동일하게 이진탐색을 기반으로한 std::lower_bound를 사용할 수 있습니다.

# CS
1. 프로세스와 스레드의 차이점에 대해서 설명해 주세요
    * 프로세스는 프로그램이 메모리와 cpu 자원을 할당받아 실행중인 상태를 의미하는 것입니다.
    * 스레드는 프로세스 내에서의 작업의 단위를 의미합니다.
        * 프로세스는 최소 1개의 스레드를 가지고 있습니다.
2. OOP 에 대해서 설명해주세요.
    * 객체지향 프로그래밍은 기능을 수행하는 객체를 만들고, 이들을 조립하듯 구조를 설계하여
    하나의 큰 프로그램을 만드는 방법을 의미합니다.
    * 2-1. 객체, 클래스, 인스턴스의 차이점을 설명해주세요.
        - 클래스는 객체를 생성하는 청사진 또는 틀이라고 할 수 있습니다.
        - 객체는 클래스를 통해 메모리 자원을 할당받아 생성된 것을 객체라고 합니다.
        - 인스턴스는 개별적인 상태를 통해 구분할 수 있는 각각의 객체를 인스턴스라고 합니다.
    * 2-2. 객체지향의 3대 특징을 설명해주세요.
        - 캡슐화 : 
            - 객체의 속성과 동작을 하나의 단위로 묶는 것을 캡슐화라고 합니다.
            - private 접근 제한자를 통해 외부에서 객체의 상태에 직접적으로 변경하는 것을 방지하는 정보 은닉의 특징을 가지고 있습니다.
        - 상속 : 
            - 클래스의 속성과 동작을 모두 이어받는 새로운 클래스를 만드는 것을 의미합니다.
            - 단순히 코드를 복사하는 것이 아닌 is-a 관계의 위계 구조를 만들 수 있습니다.
            - 클래스 상속을 통해서 클래스의 재사용성과 생산성을 높일 수 있습니다.
                - 부모 클래스를 수정하면 자식 클래스도 동일한 수정이 반영됩니다.
                - 부모 클래스의 코드를 그대로 사용할 수 있기 때문에 재사용성이 높습니다.
        - 다형성 :
            - 하나의 인터페이스로 여러 동작이나 형태를 가질 수 있는 성질을 의미합니다.
            - 주로 가상함수의 오버라이딩, 함수 오버로딩, 템플릿을 이용하여 구현할 수 있습니다.
                - virtual 키워드가 선언된 메서드를 하위 클래스에서 override 하여         개별적 동작을 수행할 수 있습니다. 
                - 부모 클래스의 포인터로 접근하여 그 가상함수를 호출하면,
                자식에 따라 다르게 구현된 동작을 구현할 수 있습니다.
3. 프로세스간 통신 방법에 대해서 이야기 주세요.
    * 프로세스는 독립된 메모리 공간들 할당받기 때문에 프로세스 간에 통신하기 위해선 특별한 방법이 필요합니다.
    * 이때 사용하는 것이 프로세스 간 통신 방법입니다.
    * 제공하는 방법으로
        1. 파이프 : 단방향 통신 채널 구성해서 통신합니다.
        2. 메시지 큐 : 메시지 단위로 큐에 저장하여 비동기 통신합니다.
        3. 소켓 : 네트워크 기반 통신합니다.
        4. 공유 메모리 : 일정 메모리 공간을 직접 공유합니다.
        5. 시그널 : 이벤트 발생 알림, 신호를 보내는 방식입니다.
4. 프로세스 메모리 구성 요소에 대해서 설명해 주세요.
    * 프로세스가 실행될 때 메모리 구성은 코드, 데이터, 힙, 스택 영역에 저장되어 작동합니다.
    * 코드 영역 : 
        - 프로그램 코드가 적재되는 영역입니다.
        - 프로세스가 시작하고 끝날 때까지 유지됩니다.
    * 데이터 영역 : 
        - 전역 변수, static 변수가 저장된 영역입니다.
        - 메인 함수가 호출되기 전에 데이터 영역에 할당되고, 프로세스가 끝날 때까지 유지됩니다.
    * 스택 영역 : 
        - 함수 호출 시, 매개변수, 지역 변수가 저장되는 영역입니다.
        - 함수의 호출이 종료되면 같이 정리됩니다.
    * 힙 영역 :
        - 런타임 중 동적할당된 데이터들이 저장되는 영역입니다.
        - 동적할당된 데이터는 수동으로 해제해주어야 합니다.
5. RaceCondition에 대해서 설명해 보세요.
    * 복수의 프로세스 또는 스레드가 공유 자원에 동시에 작업할 때,
    작업의 실행 순서나 타이밍에 따라 결과가 달라지는 현상을 의미합니다.
    * 경쟁 상태는 위해 3가지 조건이 성립할 때 발생합니다.
        - 공유 자원이 존재
        - 동시 접근이 가능한 환경
        - 적어도 하나의 프로세스가 공유 자원의 값을 수정
6. 컨텍스트 스위칭에 대해서 설명해 주세요
    * CPU가 현재 실행 중인 프로세스의 상태를 저장하고, 다음 프로세스의 상태를 불러와 실행을 전환하는 과정을 의미합니다.
        * 프로세스마다 각각의 프로세스 제어 블록(PCB)에 상태를 저장하고, 실행할 때 상태를 불러와 작업을 재개합니다.
    * 발생하는 이유
        * 컴퓨터는 한정된 CPU 코어로 다수의 프로세스를 처리해야합니다.
        * 이때, 프로세스들을 CPU 스케줄링에 따라 프로세스를 오가며 작업을 수행합니다.
    * 6-1. PCB에 저장하는 정보
        * 프로세스 ID, 프로그램 카운터, CPU 레지스터 값, 프로세스 상태 등
    * 6-2. 컨텍스트 스위칭의 비용
        * PCB에 저장, 복원하는 연산 비용
        * 프로세스 전환으로 인한 캐시 미스 발생
        * 스위칭 중 CPU가 유요한 작업을 하지 못함 -> 오버헤드
    * 6-3. 컨텍스트 스위칭 발생 시점
        * I/O 요청 발생 : 프로세스가 I/O 대기 상태로 전환
        * 인터럽트 발생 : 하드웨어 인터럽트 처리
        * 우선순위 높은 프로세스 : 선점형 스케줄링에서 강제 전환
        * 타임 슬라이스 만료 : 라운드 로빈 스케줄링에서 할당 시간 초과
    * 6-4. 프로세스 컨텍스트 스위칭 vs 스레드 컨텍스트 스위칭
        * 프로세스 컨텍스트 스위칭
            * 메모리 주소 공간 전체 교체 필요
            * 교체 비용이 큰 작업
        * 스레드 컨텍스트 스위칭
            * 같은 프로세스 내 스레드 간 전환
            * 메모라 주소 공간 공유 -> 교체 불필요
            * 프로세스보다 비용이 적음
                * 멀티 스레드를 사용하는 이유
7. 가상 메모리에 대해서 설명해 주세요.
    * 실제 물리 메모리보다 큰 메모리 공간을 사용할 수 있도록,<br>
    디스크 일부를 메모리처럼 사용하는 기법입니다.
    * 프로세스는 실제 물리 주소가 아닌 가상 주소를 사용합니다.
8. 메모리 단편화에 대해서 설명해 주세요.
    * 메모리 공간이 작은 조각으로 나뉘어 사용 가능한 공간이 있음에도 효율적으로 활용하지 못하는 현상입니다.
    * 단편화의 종류
        * 내부 단편화
            * 고정 분할이나 페이징 시, 고정된 크기로 나눠진 메모리 공간에 보다 작은 크기의 메모리가 할당되어 공간이 남은 경우를 내부 단편화라고 합니다.
        * 외부 단편화
            * 가변 분할에서 메모리 공간을 할당하고 해제되고 나서 빈 공간이 생겼지만,
            다른 메모리 사용 상태로 인해 나뉘어져 사용할 수 없는 경우를 외부 단편화라고 합니다.
    * 해결 방법
        * 압축 : 
            * 빈 공간을 한쪽으로 모읍니다. 
            * 오버헤드가 큽니다.
        * 페이징 : 
            * 고정 크기로 분할하여 비연속적으로 할당시킵니다. 
            * 내부 단편화가 발생합니다.
        * 세그멘테이션 :
            * 가변 크기로 분할하여 비연속적으로 할당시킵니다.
            * 외부 단편화가 발생합니다.
        * 메모리 풀 : 
            * 미리 고정 크기의 메모리 블록을 여러개 준비해두고, 필요할 때마다 꺼내 쓰고 사용이 끝나면 반납합니다.
            * 블록 크기가 맞지 않으면 내부 단편화가 발생합니다.
9. 캐시 히트 / 미스 에 대해서 설명해 보세요.
    * 캐시 히트란, 현재 써야하는 데이터가 앞선 작업 중 캐시에 저장되어 있어
    RAM에 접근해 불러오는 것보다 빠르게 사용할 수 있는 것을 의미합니다.
    * 캐시 미스란, 반대로 현재 필요한 데이터가 캐시에 없어 RAM에 접근해야하는 경우를 의미합니다.
