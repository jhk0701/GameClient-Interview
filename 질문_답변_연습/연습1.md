# C++ 기초
1. 포인터와 참조의 차이점
    * 포인터는 다른 변수의 메모리 주소를 가리키는 방식입니다.
        * 이때 포인터는 nullptr를 가리킬 수 있습니다.
    * 참조는 다른 변수에 별명을 지여주는 방식입니다.
        * 참조의 대상이 되는 변수는 반드시 NULL이 아닌 값으로 초기화되어 있어야합니다.
2. new와 malloc의 차이점
    * malloc은 C언어에서 동적할당하는 방식입니다.
        * 'stdlib.h'에서 제공하는 함수
        * malloc의 경우 생성 시, 할당받을 메모리의 크기를 매개변수로 보내주어야 합니다.
        * malloc은 초기화 값을 보낼 수 없습니다.
        * 반환받는 결과가 void* 이기 때문에 사용 시 원하는 포인터로 형변환 해주어야합니다.
        * malloc으로 동적할당 받은 경우 realloc 등으로 메모리 크기를 변경할 수 있습니다.
    * new는 C++에서 사용하는 동적할당 방식입니다.
        * C++ 언어에서 지원하는 키워드
        * new를 사용할 때, 동적할당할 자료형을 이용합니다. 
            * 이 때문에 별도로 크기를 명시할 필요가 없습니다.
        * new로 동적할당 시, 초기화값을 설정할 수 있습니다.
        * 반환받는 결과는 동적할당할 때 사용한 자료형의 포인터입니다.
        * new로 동적할당한 주소의 메모리 크기는 변경할 수 없습니다.
3. C++ 4대 캐스팅 방법에 대한 설명해 주세요.
    * C++에서 지원하는 캐스팅 방법은 `static_cast`, `dynamic_cast`, `reinterpret_cast`, `const_cast`가 있습니다.
    * `static_cast` :
        * 컴파일 타임에서 타입의 형변환이 가능한지 확인하고 형변환시킵니다.
        * 형변환이 불가능한 경우 컴파일 에러를 발생시킵니다.
        * 상속 관계에 있는 경우 다운캐스팅 시, 타입 안정성을 보장하지 않습니다.
    * `dynamic_cast` :
        * 런타임 중에 캐스팅하려는 타입이 맞는지 검사합니다.
        * 불가능할 경우, nullptr을 반환합니다.
        * 런타임에 타입 안정성 검사를 진행하고 상속 관계에서 업캐스트나 변환을 지원해주지만,
        다른 데이터형 변환은 허용하지 않습니다.
            * 주로 다형성을 가진 클래스의 포인터나 참조 간의 변환에 사용합니다.
    * `reinterpret_cast` :
        * 모든 포인터 유형을 다른 포인터 방식으로 변경하는 방법입니다.
        * 비트단위부터 분해, 재조립하는 강력한 형변환을 수행합니다.
    * `const_cast` :
        * `const`나 `volatile`를 제거, 부여하는데 사용하는 방법입니다.
        * 타입 자체보다는 객체의 속성을 변경하는데 초점을 맞춥니다.
            * 추가보단 제거에 주로 사용합니다.
4. RTTI와 RAII의 차이점에 대해서 설명해 주세요.
    * RTTI (Run Time Type Information : 런타임 타입 식별)
        * 런타임 중 객체의 타입 정보를 식별할 수 있는 기능입니다.
            * C++ 언어에서 제공하는 매커니즘.
        * 다형성이 있는 클래스에만 사용가능합니다.
        * 가상테이블에 저장된 타입 정보를 확인하는 방식을 사용합니다.
    * RAII (Resource acquisition is initialization : 자원 획득은 초기화에 한다)
        * 객체 생성 시 리소스를 획득하고, 소멸 시 리소스를 해제하는 방식을 의미합니다.
            * 객체가 생성될 때 자원을 획득한다.
            * 객체가 소멸될 때 자원을 해제한다.
            * 객체의 소멸은 스코프 종료 시 자동으로 보장된다.
        * 스마트포인터나 mutex를 사용한 LockGuard 등에서 사용합니다.
            * C++에선 메모리, 락, 파일, 소켓 등 다양한 자원을 직접 관리할 수 있습니다.
            * 하지만 이때, 자원 정리를 누락하는 경우로 인해서 비효율이 발생할 수 있습니다.
            * 이런 경우를 방지하기 위해서 RAII 방식을 사용하여 자원의 획득과 해제를 보장합니다.
5. C++ 스마트포인터에 대해서 설명해 주세요
    * 스마트포인터는 기존 포인터를 사용 후 해제하는 것을 누락하는 등을 방지하기 위해 만들어진 기능입니다.
        * RAII 메커니즘이 적용되어 생성 시 동적할당을 수행하고, 해제 시 할당받은 메모리를 정리합니다.
    * 포인터 관리 뿐만 아니라 메모리의 권한(소유권)을 명시하기 위해서 의도로 사용할 수 있습니다.
        * 스마트포인터는 메모리에 대한 권한 처리 방법에 따라 세 종류가 있습니다.
        * Shared_ptr, Weak_ptr, Unique_ptr 세 종류
    * Shared_ptr
        * 여러 곳에서 데이터의 메모리에 대한 참조가 가능한 스마트 포인터입니다.
        * 메모리를 참조하는 횟수를 기록하고, 횟수가 0이 될때 동적할당을 해제합니다.
        * 메모리를 공유할 때, 수명을 유지시켜 줍니다.
            * 원시 포인터로 동적할당된 데이터를 공유할 때, 한 곳이라도 먼저 데이터를 해제시켜버리면, 참조 중인 다른 곳에선 댕글링 포인터를 사용하는 위험이 따릅니다.
            * shared_ptr는 이런 문제를 방지할 수 있습니다.
    * Weak_ptr
        * shared_ptr에 대해 강참조 횟수를 올리지 않고, 참조할 수 있는 포인터입니다.
        * 메모리 생명 유지에 영향을 주지 않고 참조할 수 있기에 순환 참조로 인한 메모리 누수를 방지할 수 있습니다.
        * 또한, 강참조 횟수를 올리지 않기 때문에 댕글링 포인터가 발생할 수 있습니다.
            * 이 때문에 weak_ptr는 가리키는 데이터가 유효한지 검증하는 메서드를 제공하고 있습니다.
    * Unique_ptr
        * 메모리를 한 곳에서만 소유하도록 보장하는 포인터입니다.
            * 데이터의 소유 주체를 명시할 수 있습니다.
        * 복사 생성자를 제거했기 때문에 포인터를 공유할 수 없습니다.
            * move semantic이나 release 함수를 사용하여 포인터를 넘겨줄 수 있습니다.
        * 데이터를 소유한 객체가 종료되어 참조가 끊어지면 데이터를 같이 해제합니다.
6. 객체 복사를 막는 방법은 어떤 방법이 있을까요? 왜 객체 복사를 막아야 할까요?
    * 객체의 복사를 막는 방법은 포인터 또는 참조를 통한 얕은 복사를 이용하는 방법이 있습니다.
    * 객체의 복사를 막아야 하는 이유
        * 크기가 큰 객체를 함수의 매개변수로 사용할 때,
        그 크기만큼 스택 메모리를 새로 할당하고 값들을 복사하게 됩니다. (깊은 복사)
        * 경우에 따라서 데이터를 복사해오는 비용이 클 수 있기 때문에
        복사 대신 포인터나 참조를 사용하는 것으로 연산 비용을 절약할 수 있습니다.
